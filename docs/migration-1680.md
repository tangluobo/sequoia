# Java 操作链继续复核（1680，本轮成品检查完成）

以原 Java 的实际组件、事件与调用链为依据继续迁移，原项目保持只读。未将菜单注册、静态模型或模拟服务端的结果等同于全部实际环境验收。

## 容器属性的完整操作链

原 `ssh/ContainerInspectPane.java` 的页面包含基本信息、重启策略、资源限制、端口映射、环境变量、挂载和网络。此前 Rust 页缺少端口映射和启动命令，其他明细也仅以折叠 JSON 展示。现在恢复这些分组、可复制的只读明细、顶部刷新和底部状态；资源与策略分别应用，成功后通过同一 SSH 会话重新 inspect 回填，失败显示错误。

资源字段留空时保留服务器的原值，显式输入 0 时清除限制。内存支持原版的 b/k/m/g 后缀；修改内存时保留原有 swap 额度，无限 swap 保持为 -1，溢出、非法数字与非有限 CPU 值在执行前拒绝。这与原 Java 的 memory-swap 联动一致；相关参数定义见 [Docker 官方 update 文档](https://docs.docker.com/reference/cli/docker/container/update/)。

后台命令使用有类型的参数。读取 inspect 同时兼容数组和对象形式，取出对象时移动其所有权；页面只保留一次格式化的展示数据，不再同时长期保存完整 JSON 树与 pretty JSON，也不在每一帧重复生成明细。只读区域保持固定视口，并清除不需要的撤销快照。

进入容器终端时恢复原版的行为：优先 bash，缺少 bash 时回退 sh；继续使用已有的实时 PTY 和日志通道。

## 连接树的容器管理

原 Java 用临时 SSH 会话加载和操作树中容器，不创建工作区标签。此前 Rust 在缺少已打开会话时会创建一个 Docker 标签用于后台请求。现在改为独立的短期 actor 任务，最多 8 个任务、同一连接合并重复请求；启动/停止后重新取得列表，更新原有彩色/灰色图标，并释放独立会话和隧道资源。

密码输入沿用原加密仓库与保存冲突保护；未勾选保存时只在当前连接的内存会话中复用，连接公开参数变更后不复用旧密码。原生窗口验收强制首次缺少密码，验证一次输入后启动、停止不再反复弹窗，且配置字节不变。

另修复原生窗口中复现的焦点问题：密码弹窗出现时，后台终端主动交还焦点，避免将输入发送到远端 shell；单行密码框在回车时先失去焦点的情况也能正确提交。独立 SSH 服务端断言后台 shell 没有收到密码。交互认证在根窗口处理。取消、连接失败、超时和应用退出都释放所持任务；退出继续使用已有的并行关闭和时间预算。与原版一样，属性和存储页面不会出现仿真终端专用的标签配置菜单。

## MongoDB 文档编辑

对照 `MongoCollectionView`，点击“新建文档”后清除原选中项并将焦点交给真正的文档编辑器，可直接开始输入。焦点在编辑器实际布局时请求，避免在错误的父 UI 层级创建另一个编辑器 ID。
