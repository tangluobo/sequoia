# 表数据的数据库筛选和排序

“打开表”的工具栏、表头和单元格右键使用同一套数据库查询条件。点击“应用筛选和排序”后，
WHERE 和 ORDER BY 在数据库执行，随后才分页。快速筛选会搜索整个表，字段条件支持 AND/OR、
等于、不等于、包含、不包含、小于、大于以及 NULL 等值判断。包含匹配中的 `%`、`_` 和 `!`
按普通字符处理；需要数据库表达式时请使用查询编辑器。

排序支持多个字段及优先级调整；有主键时追加未指定的主键字段，以稳定分页中相同排序值的顺序。
没有唯一键的表无法保证相同排序值在数据库发生并发变动时保持相同位置。
分页总数与数据查询使用相同条件，变更条件返回首页；刷新、保存修改后的重新加载和后续翻页保留条件。
条件、排序或页码变化后同时回到该页顶部，恢复表格键盘焦点；相同 SQL 的刷新保留滚动位置。
“导出全部”流式读取当前条件匹配的全部记录；“当前记录”导出当前已加载的数据。

界面保留原来表格的行高、选择和编辑方式。条件草稿只在“应用”后提交，有未保存数据时先显示原来的
放弃修改确认。数据库报错保留上一次成功的页面及条件。SQL 预览存储成功读取该页面的实际 SQL，
不根据尚未应用的草稿重新生成；加载期间仍显示上一次成功语句。可选择后 Ctrl+C，或右键复制完整 SQL。
执行信息放在预览悬浮提示中，不覆盖 SQL。

字段名根据实时元数据校验并按数据库方言引用；数值按原精度校验，文本按方言安全编码，二进制等值使用
十六进制输入。MySQL BIT 将其转换为精确无符号整数比较，避免两个相邻的大数被浮点比较合并。
筛选值不能插入 SQL 语句。对 SELECT 的原字段投影保持不变；包含/快速筛选的谓词在需要时
将字段转换为文本。PostgreSQL JSON/XML 没有通用等值和排序运算符，使用原文比较；MySQL JSON、
PostgreSQL JSONB、数组、UUID 使用相应的原生类型运算。PostgreSQL NaN/Infinity 也保留数据库语义。
普通字段的大小写、排序规则和 NULL 语义由数据库决定。

不在客户端加载全部表数据：每页最多 1000 行、结果缓存最多 8 MiB。筛选与排序最多各 64 项，单个条件
64 KiB，条件文本合计 256 KiB，快速筛选 4096 字节。COUNT 与页面查询为同一会话上的两条语句，
不隐式开启长事务；其他连接并发增删记录时，总数和数据可能出现正常的瞬时变化。

交互参考 Navicat 的构建条件、多字段排序及显式应用方式，未接入其闭源代码或官方云账户：
[Navicat Filter & Sort Pane](https://www.navicat.com/manual/pdf_manual/en/navicat_17/mac_manual/navicat_mac_en.pdf)。
类型转换参考 [MySQL JSON](https://dev.mysql.com/doc/refman/8.0/en/json.html) 和
[PostgreSQL JSON 运算符](https://www.postgresql.org/docs/17/functions-json.html)；只对需要的比较表达式做转换。
本项不声称已实现其任意 SQL 表达式、嵌套条件组等全部高级筛选编辑能力。

验证记录见发布包的 `build-info.json` 与 `validation/table-filter/`；SQLite、MySQL 和 PostgreSQL
使用隔离数据源验证跨页筛选和排序，不连接旧配置中保存的主机。Oracle 生成路径已接入，未以实际 Oracle
服务器验收。原 Java 项目、加密连接文件和已发布旧包保持原样。
