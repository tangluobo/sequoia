对照只读原 Java 的 `DatabaseConnectionRecovery.java`、`DatabaseService.executeMultiSqlQuery` 和 `SqlStatementResult.errorCause`，补齐以下行为：

- SSH 首次建立数据库会话时，仅对通信故障最多尝试两次，认证和配置错误不重复尝试。已有会话或事务时，不因打开另一数据库失败而清空正常会话。
- 打开表、目录等有类型的只读请求继续使用既有三次恢复预算，连接工厂和脚本会话设置读取不会把次数相乘。
- 用户 SQL、查询结果保存发生通信故障后，清理失效会话并尝试恢复 SSH 和数据库连接；不重新发送失败 SQL，不自动继续剩余语句。失效事务保持明确提示，不自动伪造恢复。
- 脚本中断后，把已经完成的结果、执行记录和失败语句移交工作台。结果通过所有权转移保留，不额外复制整份行数据，也不先序列化成 JSON 再传回界面。
- 附加执行计划、状态和可编辑元信息读取失败时，也保留已经取得的结果。
- 重连成功时在执行信息中说明；最终失败沿用对应表格、对象列表或设计器的原生提示框，保留原表格和草稿，不在表格上方重复铺错误文字。

首次连接、用户 SQL 执行和恢复结果分别使用有类型的状态，保持 UI、服务和连接工厂分层。保留既有结果、脚本正文和执行记录的内存预算，不增加常驻连接或轮询线程。旧加密连接配置直接读取，未知字段、连接 ID 和跳板引用继续保留。
