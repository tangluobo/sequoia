# 1704：Redis 实际操作与 Hosts 旧版保存兼容

本轮核对原 Java 的 `RedisDataView`、`RedisService`、`HostsFilePane`，只按实际可达的调用路径迁移。Redis 的右键、工具栏、弹窗、后台命令和刷新继续使用同一服务适配器；Hosts 继续读取原 `.tomata/hosts_groups.json`，没有迁移个人配置位置。

## Redis

- 打开重命名、TTL 和删除确认时固定目标 Key，确认时使用该目标；右键选择不会再隐式读取另一条值，也不会操作上一次读取的 Key。
- 弹窗期间禁用后台树和编辑区，保留验证失败的输入；空名称、未改变名称、TTL 与值格式校验按实际流程处理，命令失败显示所属页面的提示窗口。
- 多选右键保留选择并显示原版“删除 (N个)”；重命名和 TTL 仅单选可用，删除确认显示最多十条完整目标名称。
- 批量删除逐项执行并继续收集服务器错误，保留连接中断前已完成的项，不把整个批次变成一个丢失细节的错误；未发送项和结果未知的超时项分别说明，不自动重放写操作。报告最多 50 条、32 KiB，截短后也释放旧字符串容量；实际故障响应包含 2 MiB 错误文字，验证保留容量受限。批次在 25 秒内结束并保留结果。
- SCAN 自动继续后续批次，包括返回空结果但游标尚未结束的批次；刷新、搜索和标签右键刷新共用重置流程，保留既有 10000 个 Key/1 MiB 目录预算，额外限制最多 4096 批，结束后清除已不存在的展开和选中项。
- 树的方向键、Home/End、翻页、范围选择和复制按焦点处理，并滚动到屏幕外目标。实际原 Java 组件已核对：Ctrl+Down 只移动焦点而不改变选择，Ctrl+Space 切换聚焦行；没有用常识假定代替原组件结果。
- 保留原版目录/数据库图标、30 像素树行高和菜单顺序；仅绘制可见行。删除后释放旧正文容量和编辑撤销状态，避免空白详情仍保留大值的历史快照。弹窗完成、取消和标签关闭时释放字段及撤销状态；错误提示关闭后恢复原输入字段，允许直接重试。

## Hosts

原 Java 使用字面量搜索 `"groups":[`、`"entries":[` 和 `"name":"`，不能读取冒号后插入空格的格式化 JSON。保存改用与原版一致的紧凑形式；保留未知根字段、分组字段、重复条目以及条目编辑/重排后的未知属性，继续使用备份、原子发布和外部修改检查。

保存失败保留草稿并显示错误窗口；明确选择“重新加载（放弃草稿）”后才重新读取，不自动覆盖外部修改。重命名和删除窗口期间锁定后台交互；初次读取不再显示“已保存”，完成提示按时收起并释放底部空间。Java 中旧的条目表单已移除，相关残留方法没有实际入口，本轮没有把这套旧界面重新加回。

## 验证范围

成品编译、检查、实际引擎及窗口结果将在通过后记录。真实 Redis 验证只使用程序自行启动的回环服务；个人加密配置和原 Java 源码保持只读。

本轮不把隔离控件事件当成物理鼠标或系统剪贴板验收，不把单机 Redis 回读当成新一轮集群、TLS 或 SSH 网络验收。原来已记录的独立协议验证继续保留。全应用像素一致、既有硬件验收与 Oracle 完整归档仍是独立项目。Hosts 在 Windows 上与原版一样需要由系统授予写权限；Linux/macOS 原版的 sudo 密码重试尚未迁移，不能把本次 Windows 保存流程计为该功能完成。

## 成品结果

989 项工作区测试通过、0 失败、103 条件忽略（66 个套件）；格式、严格全目标 Clippy 和正式 CLI 自检通过。独立实际 Redis 控件测试完成重命名、TTL、批量删除和 1100 个 Key 的多批扫描回读；正式 CLI 的五种值类型、相邻值保留、Hosts 旧版解析及冲突拒绝通过。两个原 Java 组件和两个成品窗口已逐一检查并正常退出。成品窗口使用真实回环数据，控件事件与故障边界由独立测试覆盖，未注入系统输入或写系统剪贴板。

安装器只构建和解包核对，不在用户系统执行安装。工作集/私有提交采样见 `validation/migration-1704/memory.json`；它们是空配置空闲值，不是活动连接内存上限。
