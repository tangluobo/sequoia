# 文件视图拖放上传

对照原 Java `AbstractFileBrowserPane.setupRootDropTarget/doUpload/showUploadProgressDialog` 与 `S3FileBrowserPane.preUploadCheck/doUploadDirectory`，文件列表、缩略图、分栏及下方空白区域共用拖放接收。目标是当前目录，不因鼠标落在某个子文件夹图标上而改变；未进入 Bucket 或未连接时提示原因。

S3、阿里云 OSS、旧 `LOCAL_DIRECTORY + directoryType=S3` 配置、SFTP、SSH 的文件面板、FTP、本地目录共用上传任务。拖入文件或目录后直接开始，不再额外弹出覆盖确认；同名文件覆盖，目录保留根名称、相对路径与空目录，非空 S3 目录不生成多余标记。单个条目失败后继续，最终汇总错误；完成、部分完成或取消后刷新当前目录。文件选择器也使用同一链路。

原生进度窗口保留 Java 的标题、文件索引、绿色进度、字节统计和取消按钮。关闭进度窗口表示取消，等待后台停止后关闭；关闭标签通过所有者释放取消任务。上传句柄保留到任务完成。Windows 原生拖放时补取释放点物理坐标，经原有 DPI 换算后判断落点；egui 重排不会重复提交同一次拖放。

后台扫描和传输不在 UI 帧内读取文件内容；传输复用现有连接与 64 KiB 读取缓冲，对象存储按协议最小分片使用单并发写入。全局最多两个上传任务，额外任务可在等待阶段取消。清单保留预算 32 MiB，最多 1000 个根、10 万条目、64 层，每个目录最多 2 万直接子项；不跟随符号链接。进度通知节流，普通空闲模式没有新增轮询。

Windows 接收普通文件路径和 Explorer ZIP 的 Shell 项目列表。ZIP 拖放时先记录落点和目标目录，后台由系统 Shell 提取所选条目，上传任务持有临时目录到完成或取消。Windows 压缩文件夹 API 夹具验证中文文件和目录层级；只提供 `FILECONTENTS` 的第三方拖放源及实际鼠标手势仍待验收。

验证使用自有回环 S3/OSS、SFTP、FTP 服务及临时本地目录，检查实际目标字节、层级、空文件、覆盖、MIME、单项失败后继续与活动流取消。原生窗口场景通过应用内输入夹具驱动同一控件和真实上传服务，不向系统注入输入或写剪贴板；物理资源管理器拖放需另行人工验证。未连接用户保存的主机。本地目录的普通连接入口仍为目录树，本地文件标签场景通过既有标签工厂创建，没有改变普通连接的打开方式。

开发验证通过 537 项默认回归、严格全目标 Clippy、全目标构建、格式检查与 CLI 自检；76 项按原有环境条件忽略。七个原生场景覆盖 S3 三种视图、OSS、本地文件标签、活动进度和取消，核对真实文件字节、刷新、分片清理及正常退出。原生进度截图另检查白色背景、12 像素进度条与三行文字区域；早期黑底图确实被此检查拒绝。证据为 `target/file-drop-checks-1271.json` 和 `target/window-probes/file-drop-native-dev-1272/`。
