# 主标签样式对照（2026-10-20）

运行源码检查点 `tab-style-354`。原版参考为只读 Java `ConnectModule` 创建的 TabPane、`connect-tree.css` 和同版本 JavaFX 原生皮肤。隔离场景没有创建协议连接或读写用户配置，原版节点尺寸、字体和截图位于 `target/tab-strip-oracle-349`。

## 主标签

原 CSS 的 `tab-min-height/max-height: 26px` 是内部高度，运行时还包含上下各 5px 内边距和底部 1px 边框，实际标签条为 **37px**。采用方角、无间隙布局：

| 属性 | 原版与当前实现 |
|---|---|
| 空白标签栏背景 | `#ececea` |
| 未选中 / 选中背景 | `#e0e0e0` / `#fcffff` |
| 未选中 / 选中文字 | `#555555` / 黑色 |
| 右侧与普通底边 | 1px `#c0c0c0` |
| 选中底边 | 1px 黑色 |
| 左右内边距 | 12px，另计右边框 |
| 图标 / 图文间距 | 18px / 4px，使用原资源 |
| 关闭按钮 | 16px 槽位内的小叉；对象页不占此槽位 |

原版默认及选中背景含 `!important`，实测悬停与聚焦不改变这两个背景色。保留原有未保存标记、切换、右键与批量关闭、关闭前确认等流程。内容从标签条下方开始裁剪。

标签宽度按实际显示标题测量，去掉字符数估算、90px 最小宽度和 220px 最大宽度。原版这台 Windows 的逻辑 System 字体实际为 Microsoft YaHei UI 12px；新标签通过 `java-ui` 字体族复用已有微软雅黑数据，不新增大字体文件分配，也不修改其他界面的默认字体族。

四个相同标题的原版宽度为 128 / 159 / 71 / 292px，新版为 128 / 159 / 71 / 291px。前三项一致，长标题尚有 1px 度量差异；文字墨迹边界在 1px 内。不同字体面与光栅器的像素、渐变和阴影没有全部逐像素对等，不将这些对照描述为所有状态完全一致。

## 溢出菜单

标签不足以放下时，右侧恢复 16px 的圆角下拉按钮，与标签裁剪区留 10px 空隙；水平滚动条隐藏。新建或从下拉选择隐藏标签后，自动将它滚入可见区域；滚动状态只保留在当前会话。

原版下拉是文字菜单，当前项以勾选标记表示，不显示标签图标。采用相同 23px 行高、12px 字体、白底、方角边框与蓝色悬停态。四个示例菜单行宽为 282px，边框与上下内边距合计后为 284×100px。

JavaFX RadioMenuItem 会解析标题中的助记符标记，主 Tab 不解析。下拉复现首个 `_x`、`_(x)` 及此前双下划线的显示规则，例如 `sample_db.items` 在下拉显示为 `sampledb.items`；主标签和原连接名仍保留原字符串。没有改写名称或持久化这种显示转换。菜单的原生尺寸与截图还记录于 `popup.png.popup.json` / `popup.png.popup.png`。

## 验证与范围

真实 egui 指针事件覆盖关闭按钮命中、不关闭/误选对象页、下拉选择隐藏标签及自动滚动；现有批量关闭与未保存确认回归继续执行。JavaFX 助记符行为按同版本 OpenJFX 源码验证，含转义、扩展标记和 Java 空白定义。

主标签组件独立于协议与标签控制器，services/core 和连接文件格式没有修改。图标使用原有有界缓存；弹出菜单按需创建，字体数据共享；没有保存截图或历史帧到运行态。

优化成品为 `target/qa-release-tab-style-354/release/tomato.exe`，同目录 `build-info.json` 记录 SHA-256 和证明路径。格式、严格 Clippy、开发全目标构建、优化构建与 CLI 自检通过；404 项默认测试通过、61 项条件测试默认忽略。1,447 个运行源码文件哈希一致，旧配置 59 连接 / 5 分组只读检查通过，共享文件哈希未变，原程序及历史成品保留。

开发与成品均检查了普通、选中、溢出和展开下拉菜单四个真实 GPU 窗口状态。证明分别位于 `target/window-probes/tab-style-{dev-final,release}-354/{validation,geometry}.json`。弹窗等待 5 秒后采图，排除淡入动画；JavaFX 下拉文字采用 LCD 抗锯齿，墨迹边界用亮度比较，避免把彩色子像素边缘误判为缺字或位移。

原生 RDP 两种窗口也补做回归。主标签恢复 37px 后，TAB 画面由 y=89 移到 y=90；对齐后通道差最多为 1，采用单色阶容差，不标记为逐像素一致。当前 egui-wgpu shader 依屏幕坐标加入抖动，与此差异一致。没有平移的独立 WINDOW 客户区仍逐像素一致。证据 `target/window-probes/tab-style-rdp-release-354/color-parity.json`。RDP 协议和此前流畅度实现没有修改。
