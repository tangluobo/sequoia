# 左侧连接树原位重命名

本轮以 Java `ConnectModule` 的 `TreeCell.startEdit` 和单击判定为参照，将连接树文件、文件夹、表、视图以及已存在的连接/分组、查询和备份文件/目录入口统一到同一个编辑控制器。选中后再次单击文字，延迟 300 ms 进入编辑；F2 和右键“重命名”直接进入同一个编辑框。展开箭头、图标、Ctrl/Shift 多选和双击打开继续使用原行为，虚拟分类节点不能改名。

编辑框紧接图标，在原来的 35 px 树行内垂直居中，编辑高度 26 px，字体 13 px、白底、绿色边框和 3 px 圆角，初始全选旧名称。Enter、点击外部和窗口失焦提交，Escape 取消；空名称和未改变的名称不发送任务。改变搜索条件、删除节点或替换连接来源会取消过期草稿，滚动移出可见区或切换模块则结束当前有效编辑。保留原图标，不以独立弹框输入名称。

文件操作通过已有命令队列和文件适配器，S3 使用运行时凭据做真实 COPY/DELETE；失败保留原路径。文件夹成功改名后移动缓存键、子目录路径、选中状态、展开状态和本地编辑器路径，仅重载父目录，丢弃过期列表回复。查询和备份复用各自的旧目录仓库。数据库表/视图通过已有 SQL 方言和后台变更任务提交，成功后刷新树、对象页及补全，旧名称打开的编辑标签保留内容并标记需要刷新，失败不切换为重命名弹窗。

MySQL、PostgreSQL、Oracle 使用现有对象变更适配器；SQLite、MongoDB 分类不假装支持此适配器。Oracle 未有隔离实例，因此不宣称真实 Oracle 服务器验收。连接和分组仍使用原加密配置仓库，保留 ID、未知字段、首次备份和外部修改检查，不转换用户配置。

空闲时只有一个空的 Option；编辑时至多一份草稿，撤销缓存上限 128 KiB，结束即释放。300 ms 等待只请求一次定时重绘，目录和树仍按已有缓存限制、可见行绘制，不新增常驻轮询。

验证记录与正式 EXE 哈希在交付目录 validation 中。原生截图使用隔离临时配置、真实图形后端及应用内 egui 指针事件，明确记录未发送操作系统输入；不把截图声明为与 Java 逐像素一致。网络验证只用隔离回环服务，未访问用户保存的连接，原配置未写入。正式成品与上一交付版的工作集和私有提交分别记录在 performance.md。


发布验收：746 项默认回归、严格检查和 CLI 检查通过；MySQL/PostgreSQL 的实际树改表/视图名、数据回读、重名失败保留和相关标签失效标记通过。文件实体验收含 Enter、失焦、同帧合并点击、文件夹展开缓存与编辑路径更新；查询/备份仓库、S3 认证 COPY/DELETE 与拒绝写入均经过真实 I/O。发布 EXE 四个原生窗口记录固定 35 px 行高、26 px 编辑高度、有效焦点、无 Popup 和正常退出。旧配置和上一交付物保持，配置不随包分发。
