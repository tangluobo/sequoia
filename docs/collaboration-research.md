# Navicat Cloud 调研与 Tomato Cloud 对照

调研日期：2026-10-24。依据官方产品说明、Cloud Portal 手册及桌面协作手册。实现目标是可自建的 Tomato Cloud，不冒用 Navicat ID，也不依赖未公开的 Navicat 服务端协议。

## 官方功能边界

Navicat Cloud 同步连接设置、查询、聚合管道、代码片段、模型和 BI 工作区及虚拟分组；数据库密码和原始记录留在本地。协作按项目组织，成员可管理和编辑、编辑或只读；所有者可删除项目。客户端支持变更通知、缓存和本地副本；门户提供对象预览、下载、移动、复制、成员及活动管理。账号支持两步验证。较新版本也列出个人配置同步。

来源：

- [Navicat Cloud 产品说明](https://www.navicat.com/en/products/navicat-cloud)
- [Cloud Portal 手册，第 4–6 章](https://www.navicat.com/manual/pdf_manual/en/navicat_cloud_portal/cloud_portal_en.pdf)
- [桌面协作手册，第 3 章](https://www.navicat.com/manual/pdf_manual/en/navicat_data_modeler_4/win_manual/modeler_en.pdf)
- [Navicat Collaboration 功能说明](https://www.navicat.com/en/products/navicat-collaboration?product=navicat-premium)

LDAP、AD、SSO、浏览器远程数据库管理属于其他产品/部署能力，不能仅从 Cloud 的宣传页推断其开放 API 或实现方式。官方文档没有提供供第三方重写客户端使用的完整认证与同步协议。本项目因此独立定义版本化协议；商业订阅、兑换码和 Navicat 授权也不属于自建服务的实现内容。

## 实现映射

| 工作流程 | Tomato 实现 |
|---|---|
| 多个自建服务器与账号 | 记录服务器地址、邮箱和推送偏好；会话令牌只驻内存 |
| 注册与登录 | 默认管理员建号；公开注册必须配置验证邮件；密码恢复链接有有效期且仅能使用一次 |
| 项目及成员 | 创建、重命名、删除空项目、退出；所有者/管理编辑/编辑/只读，服务端逐请求校验 |
| 邀请 | 邮箱邀请，账号内接受、拒绝和管理者撤销；支持邀请尚未注册的邮箱 |
| 对象 | 连接、查询、片段、管道、模型、BI、虚拟分组；名称、父对象、版本、正文独立保存 |
| 现有工作区 | 共享选中连接、共享当前查询副本；云端连接/分组接入原连接树；查询在原 SQL 编辑器执行与保存 |
| 文件及工作区 | 上传、原始字节下载、工作文件更新、预览和版本记录；不实现其他厂商的专有模型/BI 编辑引擎 |
| 个人配置 | 账号专属接口，便携界面设置与连接颜色/隐藏/收藏字段白名单；本机路径、API 密钥不进入同步 |
| 离线 | SQLite 本地缓存与待上传队列；先持久化再确认保存，重启和登录后续传 |
| 冲突 | 基础版本比较、稳定的提交 ID、保留两份内容；选择采用本地或远端版本 |
| 历史与删除 | 每对象最近 50 版，删除保留标记；恢复生成新版本，仍受写权限与父对象约束 |
| 跨项目 | 批量复制/移动；连接的子查询、分组一起转移；源删除与目标写入同一服务端事务 |
| 实时变化 | 最多 25 秒的长轮询；增量游标持久化；权限变化和注销会唤醒等待请求 |
| 门户 | 自带静态网页，无 CDN；项目搜索、对象类型过滤、预览/下载、成员、安全、会话与管理员用户管理 |
| 运维 | SQLite WAL、AES-256-GCM 对象加密、在线一致性备份、独立密钥恢复、TLS 或隔离的反向代理 |

这里的“同步”是工作文件同步，不是多人同时敲同一份文档的逐字符协同编辑；同时修改通过明确的版本冲突处理。模型和 BI 同步保证原始文件可回读，不能据此宣称已有完整建模或可视化分析编辑器。表配置可作为个人配置文档保存；当前应用没有实现的 Navicat 专属表配置控件不作外观或行为一致承诺。

## 关键实现决定

1. **独立存储，不改旧格式**：连接仍使用 `connections.json` 和原 Java 加密格式。云缓存位于同数据目录下 `collaboration/`，不把云登录凭据塞进旧连接记录。
2. **可回退的导入**：只更新已共享的公开属性；保留本地 ID、凭据及未知 Java 字段，通过原仓储的备份和外部修改检查落盘。
3. **可靠重试**：对象 ID 与提交 ID 分离，版本检查在服务端写事务内完成；网络中断后的相同提交不会重复产生历史。
4. **删除可同步**：删除标记与可观察事件一起提交；成员被移除后仍能看到自己的权限撤销事件，但无法继续读取项目对象。
5. **内存与退出**：后台 actor 和有界命令队列，不在绘制中访问网络；正文按对象读取，列表只保留元数据，SQL 草稿以指纹记录保存基线；关闭窗口释放已保存正文，退出中止轮询。

当前默认单对象 JSON 上限 8 MiB，原始二进制工作文件上限 5 MiB，个人配置 1 MiB，父链 64 层，每用户拥有的活动对象 5000 个/1 GiB，每项目成员与邀请共 500 个。历史有每对象 50 版的保留上限，运维备份需要同时保存数据库与加密密钥。服务为单实例部署；不宣称 SQLite 文件可作为多副本共享写入的数据库。
