## 表格配置与标签菜单

对照 `AbstractDbHandler` 和 `GlobalConfigDialog`，接入原生独立的 450×96 表格配置窗口：原有字体列表、字号、确定和取消。字体下拉从字段正下方弹出，使用独立原生弹出窗口，避免被 96 像素高的父窗口裁掉。直接读取和保存旧 `global.json` 的 `tableFontName`、`tableFontSize`；保存保留未知字段，取消不写文件。

数据页和设计表一起更新字体及对应行高，命中计算与绘制使用相同尺寸；默认设计器尺寸保留，主键粗体继续使用所选字号。字体后台加载，只保留当前字体资源对，各标签共用，替换后释放旧字节资源。Java 原组件已在隔离 JavaFX 进程截图，Rust 控件检查覆盖选择字体、修改字号、保存、取消和未知字段保留；此项几何比较不代表整套应用像素对等。

SQL 标签菜单接通“表格配置”“刷新结构”和“刷新数据”。设计表刷新走已有结构控制器，只读结构页也会重新读取定义；刷新数据继续提交编辑中的单元格、检查未保存修改并执行静默刷新，不绕过原来的保存保护。

## MQ 消费组批量删除

Kafka 和 RocketMQ 的消费组列表接通 Ctrl/Command 增减、Shift 范围、全选、保留多选的右键和批量删除。删除前显示所选名称，可取消；后台顺序执行，复用同一个协议客户端及 SSH 通道，数量、总时间、单项时间和错误文本均有限制。

某组失败时继续处理后续组，完成后分别统计成功和失败，显示失败名称和原因，刷新列表时保留结果通知。真实 Kafka/RocketMQ 由本机隔离 Java 服务提供，未连接保存的用户 MQ。RocketMQ 的消息可见性检查只轮询读取，不重放发送。该检查与合成 UI 行的菜单截图分开记录。

## Hive 实际界面流程

1672 的 Hive 后端与协议验证已经存在，但当时文档将其界面接线写得过满：若干控制器仍只识别 MySQL、PostgreSQL 和 Oracle。本轮补上 Hive 的打开连接、懒加载库、连接选择器、表设计、重命名、删除、缓存刷新和断开路径。NoSASL、Kerberos 及匿名模式不再仅因没有密码触发凭据弹窗；需要密码的 PLAIN 模式继续询问。

隔离 HS2 服务验证真实树及后台控制器：先加载库列表，仅打开指定库，读取表数据，打开设计表，添加 DECIMAL 字段，显示实际 SQL，点击保存执行一次 DDL，并刷新已打开的数据标签。随后在新查询中实际输入、执行并读取结果，断开后关闭 HS2 会话。正式 EXE 的设计表帧缓冲另行检查。模拟 HS2 是协议与界面工作流验证，不能替代实际 Hive 集群或 MIT Kerberos 域的交叉验收。

SQL 断开现在等待 SSH 监听任务释放，避免后台任务取消尚未完成时端口仍可连接；UI 线程不会等待网络任务。Hive 的不支持行编辑、导入和复制表边界参照 Java，不将其他数据库的传输按钮强行开放。
