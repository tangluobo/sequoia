# 打开表的查询与 SQL 预览

打开表的分页查询直接选择原字段，不再逐列生成 CAST、HEX 或 encode 表达式。
仍使用显式引用的列清单，以保留 MySQL 隐藏列并保证字段顺序与表结构一致。
分页、排序和默认主键排序使用统一查询计划；预览记录成功读取当前页的实际 SQL，
不从未应用的界面草稿生成语句。数据库侧筛选和多列排序见 [table-filter.md](table-filter.md)。

MySQL 和 PostgreSQL 使用现有原生会话的文本协议读取，不通过浮点数转换精确小数、
无符号大整数或日期。MySQL 的 BIT/BINARY/BLOB 直接保留字节；PostgreSQL 同时处理
十六进制和旧式转义 bytea，布尔值保持原网格及无主键原值匹配使用的 true/false 表示。
SQLite、Oracle 沿用原会话和取值方式。表页保留 1000 行和 8 MiB 的结果缓存上限，
达到上限后继续排空协议结果，避免下次使用同一会话时发生串包。

底部 SQL 预览保持 21 像素高度，文字上下居中；可以选择文本后 Ctrl+C 复制。
右键“复制 SQL”复制完整查询，执行状态在悬浮提示中显示，不会覆盖实际 SQL。
预览是只读文本，输入和粘贴不会更改查询。原行数信息、单元格编辑及连接配置不变。

本次修改范围为打开表的查询与预览。流式导出和跨连接传输继续使用各自的兼容投影。
MySQL、PostgreSQL 的 22 项隔离实例回归已通过，覆盖精确小数、BIT 位宽、二进制空值、
分页、写回、回滚、导入、备份还原和跨库传输；包括 PostgreSQL 两种 bytea 输出以及
无主键布尔域字段的原值匹配。该轮证据保留于 validation/table-sql/；最新筛选、排序、界面、
内存和源码哈希证据见发布包 build-info.json 与 validation/table-filter/。
