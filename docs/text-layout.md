## 布局修复

旧详情用 Grid 排列两列，但字段名列里面的 horizontal Ui 会请求剩余宽度，值列容易只剩很小的最小宽度。现在先测量字段名及复制按钮的宽度，所有行共用该列；字段值在独立纵向区域中按剩余宽度换行，续行保持在值列内。特别长的自定义字段名最多占 45%，省略时悬停可看完整名称。值不截断，可选择复制，offset / msgId / queueOffset 的复制按钮继续复制原值。Headers 保留显式换行与 12px 等宽字体。

消息列表分栏会重新约束缓存的宽度。详情至少保留工作区的一半（上限 340px），左列表至少 180px；宽窗口仍采用原默认分栏。窄窗口的查询页签和控件可换行，避免输入控件反过来撑开左列表。

元数据使用原 Java 的 12px 文字、8px 内边距、8px 列间距、4px 行间距、#f8f8f8 背景与 #e0e0e0 边框。每行先测量换行高度，再把字段名和复制按钮放在该行中间，修复字段值相对字段名下移 8px 的偏差。窄表格表头在列内省略并裁剪，避免挤入相邻列。Java 和 egui 的字形与行度量仍可能有约 1px 差异，没有宣称所有界面逐像素一致。

Windows 普通 UI 文字复用主标签现有的 Java UI 字体顺序，避免 Segoe UI 和中文回退混排时使用不同的行度量。连接树采用原版 12px 字体、保持 35px 行高和原图标；类型选择、工具列表标题和描述也统一字体。数据库数据网格、主标签和终端的专用字体设置未改。没有新增字体文件、副本、依赖或常驻数据缓存；旧配置格式和共享连接文件不变。
