## 原生实现

- MySQL 新建与修改表支持引擎、默认字符集、排序规则、自增值、行格式、平均行长。SQL 预览和执行共用 core 方言投影；服务端回读更新草稿及相关标签。平均行长读取配置值，不把数据统计值误当成配置。清空已有选项、无效整数及 SQL 片段会在执行前拒绝。
- 复合外键及触发器支持添加、删除、SQL 预览、保存和回读。新表可以一并定义，既有表继续使用同一保存 actor。复合字段支持逗号和 SQL 引号转义；PostgreSQL 触发器填写既有触发函数调用，MySQL 支持单语句和 BEGIN/END 触发体。
- 已有外键/触发器只读查看，可明确删除、重新添加。未修改的定义不重建、不重放，保留未展示的属性和函数内容。MySQL/PostgreSQL 的元数据签名还覆盖界面未展示的定义、执行上下文或启用状态，提交前发现外部修改则拒绝整次保存。
- MySQL 自增值从已读取的 SHOW CREATE TABLE 提取，绕开 INFORMATION_SCHEMA 的统计缓存。普通插入导致 MySQL 自增计数变化时，允许保存无关结构；明确修改自增值时仍检查计数是否变化。PostgreSQL 使用事务/保存点；MySQL/Oracle/Hive 的 DDL 可能部分提交，失败明确提示核对实际状态，保留草稿。
- PostgreSQL 新建/另存为不再忽略自动递增、默认值和列注释；记录 ALWAYS/BY DEFAULT/Serial 来源，保留原生默认表达式和生成列。既有整数列关闭/重新启用自动递增时，保留数据并把新序列移到最大值之后。Oracle 新建投影接入数值标识列/默认表达式/虚拟列，但仍缺少本机引擎验证，既有 Oracle 标识属性继续明确要求通过 SQL 修改。
- 原 Java 的原始 SQL 样本保留；新建 native-create-corrections.json 明确列出原版忽略的设置和不合法类型组合，避免以忽略设置生成无效 SQL。
- 查询执行器、预览 SQL 和相关脚本入口共用方言拆分器。PostgreSQL 支持带标签/无标签 dollar 引号及嵌套块注释；MySQL 支持 DELIMITER、反引号、复合程序体及内部 CASE/END IF 等，保持普通 BEGIN/COMMIT 为独立事务命令。执行器读取真实会话字符串模式，显式 SET 修改模式后同步更新拆分器和事务跟踪；安全的初始模式读取可重试，已执行的用户语句不重放。普通 Java 兼容拆分接口保持原语义。
