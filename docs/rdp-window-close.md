# RDP 独立窗口关闭

本轮对照 Java `RdpConnectHandler` 的窗口隐藏后断开会话、关闭标签后关闭窗口的生命周期修复 Rust 独立窗口；不修改 Java 项目或共享连接配置。

复现了两条应用层问题：最小化/遮挡窗口执行逻辑更新而没有绘制时，关闭请求没有处理；会话设置打开时，原关闭分支会发出 CancelClose。新的关闭处理在逻辑阶段先检查原生窗口事件，绘制回调也保留相同的早期关闭路径。关闭仅移除对应窗口/会话，并取消它自己的会话设置草稿；其他窗口及其设置继续保留。全屏还原到标签后，迟到的原独立窗口关闭事件不会断开保留的标签会话。

原生实连进一步发现，只有应用层处理仍不能保证及时回收窗口：子窗口会话释放后，合并的主窗口重绘请求可能没有及时执行，原生窗口保留。框架现对接受的子窗口关闭显式调度主窗口原生更新；全树最小化时执行一次不呈现的主窗口 UI 更新，让框架回收子窗口注册、输入和 GPU 表面。当前子窗口被回收后，发给其余窗口的命令也继续分发，避免主窗口关闭命令在提前返回时丢失。正常隐藏空闲逻辑保持原节流。

回归包含最小化/遮挡且没有 UI pass 的关闭、会话设置所属关系、等待握手时关闭实际 loopback 套接字、连接失败时关闭、全屏还原后迟到事件。修复前两项回归失败，修复后原生窗口路径也单独验收。验收通过应用自己的原生窗口命令触发相同的 Close 事件，记录子窗口从原生列表消失、主窗口仍存在、最小化状态与正常退出，不注入操作系统输入。

开发构建实连证据为 `target/window-probes/rdp-close-linux-dev-1000/validation.json`：小主机桌面普通窗口约 221ms 移除，主窗口和子窗口均已最小化时约 143ms 移除，主程序保留。后续默认 Vulkan 后端重复实连也通过，见 `rdp-close-linux-dev-auto-1010`。

正式 EXE 为 `target/qa-candidate-rdp-close-1008/tomato.exe`，默认 release 优化、98,792,960 字节，SHA256 `D00742FCDD42F565E7CF00C4E65CCB493691A79E584200CC4B21F3264F11CA57`。冻结的 2,169 个生产文件校验一致；499 项默认测试通过、73 项条件测试忽略，另外四项协议向量、格式、严格 Clippy、全目标构建和 CLI 自检通过。PE 图标全部帧与原资源逐字节一致。

同一成品实际连接“小主机桌面”，默认 Vulkan 普通窗口约 215ms 移除，双窗口最小化后约 133ms 移除，主程序仍存在；证据 `target/window-probes/rdp-close-linux-release-auto-1011/validation.json`。标签/独立窗口的连接与整体正常退出另由 `rdp-close-linux-release-tabs-1012` 验证。截图已检查，显示 AlmaLinux 图形登录界面，没有代用户登录 Linux 图形账户或测试物理输入性能。旧四份配置与前版 983 EXE 的校验值保持一致。

独立 loopback RDP 服务也验证成品：Vulkan 普通窗口关闭约 194ms、双窗口最小化后约 35ms，DirectX 12 全屏关闭约 55ms，详见 `target/rdp-close-loopback-release-1013.json`。当前 Windows RDP 会话下，Vulkan 全屏在创建子窗口 GPU 表面时出现 `Invalid surface`，尚未进入关闭验收；前版 983 在同环境也复现，证据 `rdp-close-fullscreen-old-1015`。该项不标记为通过，DirectX 12 的全屏通过记录独立保留。此问题不据此归因为关闭逻辑。内存测量另见 [性能记录](performance.md)。
