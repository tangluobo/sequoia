# 1702：JSON 与消息正文交互补齐

本轮直接对照当前 Java 的 `JsonToolPane`、`JsonFoldableTextView` 和消息详情调用路径。未把工具注册或模型存在当成完成功能；实际只读输出区域、工具栏和消息双击打开流程均接入了对应控制器。成品检查结果与验收边界见文末。

## 实现范围

- JSON 与 RocketMQ/Kafka 共用的正文支持鼠标拖动选择、跨滚动回溯选择、Shift 扩选、双击选词和三击选行。方向键、Home/End、PageUp/PageDown、Ctrl+A/C 作用于当前聚焦的正文，不影响输入编辑区。
- 选择边界按 Unicode 字素簇移动，避免把组合字符、中文或 emoji 的 UTF-8 字节切开。按当前可见折叠内容复制；展开、折叠和重新赋值后重置旧选择，节点复制仍复制完整节点。
- 原 Java 的 TextArea 与 RichTextFX 换行语义分别处理：普通 JSON 文本移除 CR；消息先解析，只有纯文本回退时才把 CRLF 和独立 CR 规范为 LF，保留前后空行。宽松 JSON 字符串里的真实回车先解析并转义，保留其值。RichTextFX 的 Ctrl+Right 停词尾，TextArea 停下一词开头，使用实际原版键盘处理结果核对。
- 固定 70 像素行号栏；原版行号、展开箭头和节点复制图标的位置与选区蓝色取自实际原组件。复制图标的命中区止于正文起点，避免挡住第一个文本字符。
- JSON 历史记录支持聚焦、键盘导航和选中项滚动可见；键盘选择不自动恢复历史内容，鼠标点击保留原流程；右键顺序为“删除此记录”“复制JSON”。
- RocketMQ 与 Kafka 消息双击后默认格式化正文，保留 `null` 和 HTML 字符。压缩后再展开会先重新格式化；纯文本禁用格式化及折叠按钮；工具栏复制当前可见正文。刷新消息列表会清除旧正文，避免详情残留。
- 消息正文复用核心中原版 Gson 语法的解析器，支持单引号、注释、未加引号的键和顶层原始值，并保留数值原文。仅无法按原语法解析的内容走纯文本显示；单个未加引号的词按原 Java 转为 JSON 字符串。配置文件继续使用独立的严格解析器。

## 内存与边界

正文不另存整份选择快照，只保留起止位置；真正复制时才生成所选字符串。绘制使用可见行，长行使用稀疏位置索引，单次窗口最多 4096 字节、最多缓存 128 个长行度量。零宽组合字符也受窗口大小约束。清空正文时释放行索引、节点索引、选择状态和长行缓存的旧容量。原语法解析复用既有的 8 MiB 输入和节点预算，格式化复用既有的 32 MiB 有界写出器，协议和网络调用仍位于服务层。

本轮未改变 MQ 网络传输实现。原 Java 消息详情的两个格式按钮存在重复切换行为，本版保留已有的真正压缩功能，并让随后展开恢复结构；没有刻意复制原版这个缺陷。完整应用视觉、物理输入、实际消息服务器及既有硬件相关验收，不能从此轮隔离正文夹具推断通过。迁移清单继续明确保留未完成项。


## 本次成品结果

983 项工作区测试通过、0 失败、102 条件忽略（65 个套件）；格式检查、严格全目标 Clippy、CLI 自检及旧加密配置只读检查通过。原 Java 七个实际组件场景采集完毕，成品八个原生窗口中的 17 次复制命令逐字节匹配原版输出，窗口均正常退出。覆盖结构化 JSON、完全折叠、原始长行、RocketMQ、Kafka、消息折叠、消息纯文本、宽松语法和顶层原始值。

本轮窗口由应用自有输入钩子触发实际控件事件，复制命令在交给系统前拦截；没有写系统剪贴板、注入系统输入或连接保存的主机。消息来自隔离夹具，没有把这八个窗口算成消息服务器传输验收。七个原 Java 截图和八个成品截图已逐一检查，不据此声明全应用像素一致。原版键盘测试只将 Ctrl+词、Home/End 作为稳定参照，未声称全部垂直导航像素对齐。
