# ADB 连续视频

2026-11-24 起，ADB 标签可以移到独立窗口并返回，两个位置使用同一会话。ADB 使用内置 Rust TCP 直连。下文保留早期实现的验收记录。[当前配置与连接方式](adb-settings.md)

## 2026-10-20 画质修正（adb-quality-365，验证中）

未设置画质参数时，视频保留原来的 1920 长边上限，码率从 8 Mbps 提高到 24 Mbps，保留 60 FPS 上限；超清档为 2560 / 24 Mbps，原生档为设备分辨率 / 32 Mbps，流畅档仍为 1024 / 4 Mbps。界面和服务端共用一份类型化预设，选择后会重连真实编码器，重新选择当前档位也会应用新参数。旧配置中明确保存的尺寸、码率继续优先，切换只作用于当前标签副本，不写连接文件。

I420 三平面在 GPU 使用线性采样，修正原来的最近邻缩放：1:1 亮度像素保持中心对齐，非整数缩放及半分辨率色度采用平滑重建。仍使用三张持久 R8 纹理，增加一个共享采样器，没有 CPU 整帧重采样、额外整帧缓存或显示队列。H.264、后台解码和最新帧消费路径保持；没有通过降低 FPS 换取画质。

解码积压时，原路径一直等待压缩队列清空才发布画面，可能长时间只解码不显示。现在首次完成的画面可以立即发布；积压期间按至少 8ms 的发布间隔推进最新已解码画面，继续保留所有参考帧和原有队列预算。正常无积压时沿用原发布路径，隐藏标签继续跳过像素打包和 UI 唤醒；没有增加显示缓存深度。

364 原型的实际优化窗口对照已验证采样修正：25,993 个细字区域采样点，对解码帧双线性参考的红通道平均误差从 3.595 降为 0.122。这是显示采样误差，不是整体画质提升百分比。原型 1080p 动态画面约 54.67 次/秒、整屏变化约 52.89 次/秒，2560×1440 细节动态画面约 35.81 次/秒；因此最终策略保留默认 1920，并继续修复积压发布。364 没有作为最终交付版，365 需要重新验收。

本轮另确认 PowerShell / .NET 的环境恢复问题：把 `$null` 传给 `SetEnvironmentVariable` 会得到空字符串，空 `WGPU_BACKEND` 会禁用全部后端，导致此前连续内存探针启动失败。使用 `[NullString]::Value` 恢复真正的不存在状态，十个相关窗口验收脚本已修正。同一 364 成品的空值/不存在对照分别复现失败/正常启动，证据 `target/adb-quality-env-causality-364.json`；这些诊断启动数据不作为最终运行内存数字。

2560 是长边上限，设备本身低于该分辨率时不会增加原始细节；码率是编码目标，实际吞吐和帧率取决于硬件编码器、解码负载及网络。原生档可能增加内存与解码负担，不承诺所有设备都能以原生分辨率达到 60 FPS。scrcpy 对尺寸、码率和 H.264 延迟的说明见 [对应版本官方文档](https://github.com/Genymobile/scrcpy/blob/v3.3.4/doc/video.md)。

## 实际链路与兼容

旧配置中的 adb 路径 / endpoint → 唯一的设备端 server 和转发 → 持久 H.264 视频连接 → 后台 OpenH264 → 最新一帧 I420 → GPU BT.601 转色。GUI 复用三张 R8 纹理，只上传紧凑 Y/U/V 平面；不在 CPU 端展开整帧 RGBA。没有 GPU 接收方的客户端仍可使用 RGBA 输出，PNG 截图兼容路径也保留。宿主不需要外置 FFmpeg 或 scrcpy 程序，仍需原有 Android platform-tools。

默认上限 60 FPS、长边 1920、8 Mbit/s。原工具栏的流畅视频 / 稳定截图、高清 1920 / 原生分辨率 / 流畅 1024 均接入真实协议和重连。服务启动不兼容时显示原因并回退 PNG。模式与画质只修改当前连接标签的副本，不改写原连接文件。

触摸 DOWN、按住时的实时 MOVE、UP 和导航键通过持久控制 socket 直接发送；连续移动可以合并，按下、松开、尺寸变化与按键保持次序。尺寸变化取消旧手势，文本保留原版 ASCII 输入约束。关闭只清理自己的唯一转发、临时 JAR、子进程和 socket；不会 disconnect、kill-server 或 remove-all。

## 内存与显示

1080p 的一帧 I420 为 3,110,400 字节，RGBA 为 8,294,400 字节：GPU 路径的像素上传量减少 62.5%，不是进程总内存减少 62.5%。每个标签只保留最新源帧和三张持久纹理，重绘相同源帧不会重复上传。分辨率变化才替换纹理；关闭标签释放其画面资源，共享着色程序缓存有界。

压缩包最多 8 MiB、参数集 128 KiB，队列最多 90 包 / 250 ms / 8 MiB。过载等下一关键帧并重建解码器，不丢依赖帧后直接解码后续 P 帧。帧最多 8M 像素，宽高最多 8192，SPS 参考帧最多 16 且参考像素预算 32M，先验证再交原生解码器。后台标签超过 250 ms 不消费时跳过像素打包 / 颜色转换和 UI 唤醒，继续维护视频参考链，重新进入时取新画面。这些是各缓冲预算，不是全进程或 GPU 驱动峰值上界。

GPU 着色与 CPU 兼容路径使用同样的有限范围 BT.601；根据渲染目标处理 sRGB，保持原画面几何、最近邻缩放和裁剪。没有增加显示缓冲深度，也没有改为撕裂显示。
