# 1700 图片与数据集转换迁移

原版 `ImageFormatConverterPane` 会递归处理目录、保留相对路径，并继续处理失败项；此前 Rust 入口只遍历第一层且遇错中止。原版 `DatasetConverterPane` 也会递归查找 XML、忽略不完整标注并输出完整 COCO 信息。此次把两条流程接入共享命令处理器和后台任务，保留旧 CLI 调用方式。

图片转换支持单个 SVG 与嵌套目录，保留同名文件所在的子目录；每项独立计数和原子发布。损坏文件不会清空已有 PNG，其他项目继续转换。数据集转换支持 UTF-8、UTF-16、声明编码、中文及全角空格，按原 Java 处理缺失字段、无效对象、负坐标和越界坐标；补齐 info、licenses、image 元信息、segmentation 与 iscrowd。所有 XML 无效、取消或写入失败时保留原 JSON。

界面使用原版标题、图形路径、标签、按钮文字、控件尺寸和完成提示，并按原 Java 895×600 组件测量位置。错误归属当前工具，不借用全局处理提示；后台队列拒绝后恢复按钮，关闭标签触发取消。新的标题 SVG 已加入显式资源注册。完整应用像素一致性仍需另行验收。

服务按职责拆为目录遍历、SVG 渲染和 VOC/COCO 转换适配器；GUI 与 CLI 使用同一请求和结果类型。目录遍历不预存整个文件清单；COCO 图片直接写出，标注使用临时流，最后按 64 KiB 分块复制并检查取消，不在内存中保存全部标注。每批只建立一份字体数据库；转换共享单个并发许可，许可随阻塞任务释放。

资源上限为目录深度 64、SVG 输入 8 MiB、输出 6400 万像素、单个 XML 8 MiB/262144 节点、类别 65536 个/名称合计 4 MiB。禁止 DTD 和外部实体。上限保护异常输入；不表示与 Java 的无限输入行为完全相同。

原 Java 当前组件在隔离夹具中实际点击转换，生成三种完成状态及窗口快照。Rust 比较 PNG 实际像素，以及忽略日期、目录枚举顺序和对应 ID 后的完整 COCO 内容；另外有递归、坏输入、编码、已有结果保护、取消和队列拒绝的服务与实际控件回归。未使用保存的连接，也未注入实体鼠标或键盘；文件选择器的实体操作和处理中手动关闭窗口不计为已验收。

最终优化程序、实际窗口、数据库回归及内存数据以本次发布的 `validation/migration-1700` 记录为准。原 Java 539 份主源码及旧加密配置保持只读；25 种连接图标重新逐字节核对。其他工具的九项路由检查仅证明注册和路由，不据此宣称全部功能或视觉对等。Oracle 完整复制/归档、原有实际硬件和全应用视觉验收仍保留在迁移清单中。
