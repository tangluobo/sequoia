# 数据库连接恢复与表格错误提示

数据库工作台在读取表数据、结构、库/表/对象列表、补全和设计器元数据时，识别错误链中的传输异常，包括 Windows 10053/10054、连接重置、EOF、断管、连接拒绝和超时，以及数据库连接失效状态码。

读取失败后清除该连接的失效数据库会话和 SSH 隧道，沿用原连接参数建立新会话，然后重新执行原读取请求。最多三次尝试，恢复在后台完成；不会先把中间错误显示到已加载的表格上。沿用原连接建立超时，尝试间使用短暂退避，不另外缩短正常 SQL 的执行时间，不创建无限重试任务或额外后台连接池。

SSH 转发与数据库会话一起重建，兼容引用跳板和旧的内嵌 SSH 配置。跳板认证和主机密钥检查继续使用原逻辑；隧道的 SSH 会话断开后释放监听端口及转发任务。连接凭据不会因此写回配置。

普通 SQL 语法、字段、权限等错误不会被当作断线无限重试。保存、删除、DDL、事务控制和任意手写 SQL 不自动重放。连接中断时清除失效缓存并说明提交结果需要核对，防止重复写入。SQL 脚本遇到传输中断会停止剩余语句，不在新会话中继续后续写入；执行计划或附加状态读取时断线也会报告连接失效。显式工作台事务及常见手写事务控制语句保留活动状态；事务失效时不在新会话中悄悄继续原读取。

“打开表”收到最终错误后使用原有 OpenJFX 风格的独立错误提示窗口。原表格、选择、编辑草稿及上一次成功的 SQL 预览保留，确认后仍可刷新重试；错误文字不占用网格上方空间。事务丢失后暂停陈旧页面的写入，刷新成功再恢复，避免用“修改已保存”的结构刷新提示误导用户。

验证范围：源码检查、断线分类和有限重试测试、原生提示窗口回调、保留页面/草稿/布局测试，以及隔离 MySQL/PostgreSQL 的数据库直连和原生 SSH 断流测试。最终执行结果以发布包内验证记录为准；测试仅连接自建本机夹具，不访问用户配置中的主机。
