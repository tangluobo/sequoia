## 文件标签和目录拖出

- 原 Java 的 SFTP、FTP 和 S3 标签都有“刷新／会话配置”。Rust 的 FTP、S3/OSS 原先没有菜单，SFTP 则进入了终端菜单。现在由独立 `app/file_tabs` 控制器提供原菜单，刷新当前目录并由原后台调度器合并请求；会话配置复用加密仓库和保存冲突保护，显式文件视图选择应用到已打开的对应连接。
- SFTP 和 S3/OSS 的初始图标视图、FTP 的列表视图对照各 Java 构造函数保留。FTP 的多列视图仍按原 Java 的 `supportsColumnView=false` 限制；没有把配置中的选项误算作 FTP 已实现多列浏览。
- 系统拖出原先先递归枚举目录，完成后才交给 Windows。现在立即提供所选根项目的元数据，松手后才取得完整目录清单和源文件内容。仍支持多选、嵌套中文路径、空文件与空目录、Windows 复制进度；保留 4096 项、64 层和 8 MiB 元数据限制，不新增后台常驻线程或整文件内存缓存。
- 原生 COM 边界集中在 `native-drag`。悬停时查询格式或拖动状态不会调用远端枚举；目录枚举失败会保持失败结果，避免后续查询把失败当作空目录成功。取消会唤醒等待清单的接收方。

原生拖放遵循 Microsoft 的 [Shell 数据对象约定](https://learn.microsoft.com/en-us/windows/win32/shell/dataobject) 和 [Shell 剪贴板格式](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard)。组件边界检查使用真实 Windows Shell 接收目录；不能用此替代人工资源管理器拖动的使用验收。
