# 表格选区批量输入（1666，2026-10-30）

打开表、普通查询和脚本查询结果支持选中多个可编辑单元格后直接键入同一个值，无弹框。复用 Java TableDataView 的批量输入行为：首次输入替换选中字段，后续输入与 Backspace 同步显示，Enter 确认，Esc 撤销这次输入；Tab、方向键或鼠标切换结束批量输入。确认只进入原有待保存数据，点击保存才执行数据库回写。只读结果、生成列和查询表达式列不会被批量覆盖；保留主键等原始行条件及已有未保存修改。

两个网格共用有界的键盘/IME 控制器和输入缓冲，通过各自的编辑适配器提交。输入期间保存物理单元格地址及一份文本，不克隆结果页、原始值快照或每次按键的整批行数据。中文组词会替换预编辑文本，候选确认不触发单元格编辑器。确认时先验证整批，类型或容量验证失败时保留输入并允许修改或 Esc 撤销，不留下部分写入。批量编辑计入标签关闭与表格刷新时的未保存修改保护。

上限为 1,000 行、65,536 个单元格，值的预计总量 8 MiB；打开表提交暂存上限 16 MiB，查询结果总待保存上限 8 MiB。批量输入的绘制只读取每个可见单元格前 160 个字符，复制和保存保留完整输入。未新增缓存线程和字体、图标资源。

815 项默认测试通过、0 失败、90 项条件忽略；格式、严格 Clippy、CLI 自检、旧配置只读检查通过。完整 SQL 面板事件回归覆盖拖选、Shift/Ctrl 多选、物理行映射、已有草稿回退、中文输入、批量原子校验、只读列、保存按钮和复制粘贴。保存按钮的真实命令在隔离 SQLite 文件中执行，核对只有选中字段改变；查询结果核对实际 SaveQueryRows 命令的原始条件及修改字段，沿用已有 MySQL/PostgreSQL 回写服务。本轮不声明对保存主机进行新的数据库联机验收，也不声明人工 Windows 输入验收。保留 1664 快捷键修复、1662 边线、之前的终端/数据库恢复及工具、云服务端和历史验证记录。
