# 右键菜单宽度

对象页的菜单内容和操作继续对应原 Java `TableObjectsView.setupContextMenu`，同时应用于图标视图、详细列表和内容空白区。打开表、设计表、新建表、新建查询、复制表、清空表、截断表、删除表和刷新使用原图标及原有命令路径。

原问题在共用 `compact_menu::Item`：egui 新弹出层用 600 逻辑像素作为建议区域，菜单在测量阶段直接占用这个可用宽度；分隔线也占用相同区域，导致短菜单被撑宽。现在测量阶段按实际字体的文字、图标和边距计算宽度，普通菜单保留原有 150 逻辑像素的内容最小宽度。分隔线在测量阶段不贡献宽度；可见阶段所有菜单项和分隔线填满测量后的区域，整行保留点击和悬停响应。较长文字仍可扩宽菜单，不硬裁文字。

普通菜单的行高仍为 23，分隔线为 3；打开表数据菜单沿用独立的 20 像素行高和内容宽度计算。粗体项目按实际粗体字体测量，避免收窄后裁切文字。修正没有新增运行时缓存、依赖、配置字段或后台重绘任务。

回归使用真实对象菜单、鼠标右键和左键事件，覆盖四种缩放的宽度稳定性、菜单右侧点击刷新和点击后关闭。`scripts/qa/object-menu.ps1` 使用独立空配置，在原生窗口的图标/详情两种视图打开菜单，以实际帧缓冲的外框和四条分隔线测量宽度、行距及正常退出，不连接保存的主机、不写系统剪贴板。原生夹具的多视口输入位置及选区不据此标为验证完成，菜单点击行为以单视口的实际 egui 输入回归单独验证。此处不据此宣称 JavaFX 与 egui 字体栅格化逐像素相同。

验收完成：492 项工作区测试通过、0 失败、72 项条件测试忽略；格式、严格 Clippy、全目标构建和 CLI 自检通过。成品四张对象菜单原生截图均测得 164×233，分隔线偏移为 100、126、175、201；打开表的单行、多行和单元格三个原生菜单与原 Java 的 114×255 布局回归通过。成品 `target/qa-candidate-menu-width-960/tomato.exe`，证据和身份见同目录 `build-info.json`。四份共享旧配置及上一版 EXE 哈希不变；图标六尺寸检查通过；空闲内存配对结果见运行内存文档。
