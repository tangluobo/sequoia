# 文件视图内容区与框选

对照只读 Java `AbstractFileBrowserPane.initIconView`、`updateRubberBandSelection` 和 `S3FileBrowserPane` 的边缘自动滚动逻辑，修正共用文件浏览器的布局和选择行为。S3、阿里云 OSS、SFTP、FTP 与本地目录使用同一实现；FTP 继续保持原来的图标/详情列表两种模式。

独立文件页的详情列表、图标/缩略图和多列目录视图至少填满剩余内容高度。移除文件内容结束位置的额外分隔线，底部状态栏仍固定在内容区之外。文件较少、空目录时，下面的空白也属于文件视图。终端侧栏的多个工具块继续使用原来的分隔布局。

鼠标左键从空白处按下开始框选；普通框选随矩形重新计算选中项，缩小矩形会移除不再覆盖的项。Ctrl/Shift 可追加选择，空白点击清空普通选区。鼠标释放结束框选；切换目录、筛选、模式、重新排序、弹出菜单、失焦或 Esc 取消活动选框。点击文件本身继续使用已有选择、打开与编辑行为，右键不会启动框选。

选框坐标相对文件内容保存，拖动到视口边缘时请求滚动及后续绘制，滚动后锚点仍对应原来的文件位置。选框采用原版蓝色 1px 边框和约 15% 透明填充。只在活动拖动时扫描选框覆盖的文件，列表绘制仍限制于可见行，不创建空白占位项、不复制缩略图缓存、不更改旧连接配置。

验证记录会区分实际 UI 控件事件、原生窗口截图和旧版像素对照；代码接入不等于全部页面已经逐像素一致。

工作区默认回归 473 项通过、70 项条件测试忽略，见 `target/file-views-validation-654.json`。新增四项真实控件事件回归覆盖 14 组协议/视图组合，检查空目录/少量文件的底部空白点击、选框收缩、释放、追加选择、文件点击隔离、筛选取消及键盘全选。千条目录通过滚轮滚到底部并反复滚动，确认底部位置稳定；按住指针靠近边缘能继续滚动且保留内容锚点。万条目录在三种视图中只产生可见项的绘制形状，未创建万条空白行。这不是进程内存下降的测量结论。

原生窗口另发现根目录首次加载会增加一个空白历史列。同一路径的列表响应现在只更新文件，不再推入或清空目录历史；避免空列和无用目录副本。真实本地 S3 会话的首次加载、刷新、图片打开/下载/删除回归通过。开发版三种原生窗口及内容区像素检查通过，见 `target/window-probes/file-views-dev-fixed-648`，多列根目录已回到单列。

运行源码冻结为 `target/checkpoints/file-views-650/sources.zip`，与上轮 629 核对仅有预期文件视图、框选、验收夹具和文档变化。之后的成品与原生窗口证据独立记录。
