## 已落实的策略

0.1.3 均预热 15 秒、采样 10 秒。最终构建及其重复测量报告位于 `target/memory-0.1.3-{auto,vulkan,auto-repeat,vulkan-repeat}.json`；低功耗试验报告为 `target/memory-0.1.3-low-power.json`。这些是隐藏启动、空闲无连接场景，不包含活动 SSH / RDP 会话。低功耗偏好在本机反而占用较高，因此没有改为默认。

初轮与最终构建之间的源码修改仅涉及 SSH 启动输出保留，尚未隔离系统负载、图形驱动缓存和窗口隐藏状态等因素，不能将跨轮内存差异归因于该修改。旧便携包初轮配对 Vulkan 复测为 164.22 / 205.59 MiB，与更早的 126.65 / 205.91 MiB 也不同。最终两次重复测量较接近，仍不是对其他机器、可见窗口或活动会话的保证。

- 保留原版字体和布局；资源按需解码，图标缓存最多 64 项。
- 连接树只绘制可见行，不在每帧复制全部连接配置。
- 终端输出以 Observer 通知重绘，空闲时没有 40 ms 轮询；输出通道最多 32 个 4 KiB 块，历史默认 1,000 行，沿用旧配置时最多 100,000 行；更大的回滚设置会增加终端驻留内存。
- 0.1.6 光标使用 egui 单调时钟，仅请求下一个 500 毫秒边界；没有每个终端独占的线程或计时任务。隐藏标签、远端隐藏光标、浏览回滚、文件独立面板及最小化状态不安排光标重绘；监控或协议输出仍可独立唤醒界面。
- 0.1.7 跨回滚选择直接借用 vt100 现有历史单元格，以稳定行号追踪被淘汰的行，不增设历史副本。松鼠标后只保存一份选中文本快照（最多保留 16 MiB）；复制较大选区仍会产生临时字符串，这不是整个进程内存上限。边缘拖选的 16 毫秒重绘仅在拖动期间启用。
- Markdown 解析由共享 CommandHandler 在后台执行，源文档上限 8 MiB、结构上限 20,000 个块；编辑后 250 毫秒防抖，旧版本解析回复被丢弃。预览只排版可见块，代码块只生成可见行的字形；编辑区仍使用完整 TextEdit 排版，不能称为整个编辑器虚拟化。图片按需在后台加载，编码数据最多 8 MiB、解码分配限制 64 MiB、显示纹理最多 1600×1600，每编辑页保留的图片像素预算 16 MiB。HTTP 请求有超时，关闭标签释放其缓存；已在进行的共享后台读取可能执行到完成，不能把标签关闭说成同步取消所有 I/O。
- 本地连接树后台逐层加载，一次目录最多 5,000 项、列表估算数据最多 8 MiB；每个连接最多缓存 64 个目录、10,000 项，全树列表估算数据预算 64 MiB。只生成已加载的行描述并绘制可见行，刷新丢弃对应子树缓存，删除或改配连接释放缓存。路径键、容器元数据及任务开销不包含在列表数据预算中，不能把它称作进程总内存上限。
- 每轮界面逻辑最多解析 64 KiB 终端输出，达到预算后安排下一帧继续；持续高速输出不会让读取循环一直占用 UI，队列背压保留输出而不丢弃数据。
- JSON 历史沿用原版 50 项上限，界面仅保留时间、摘要和记录标识；完整文档按需从原历史文件流式读取，单项最多 8 MiB。输出按索引绘制可见行，折叠状态不复制整份文本。
- SQL 默认保留 1,000 行，可配置至 10,000 行；跨结果集值数据最多 8 MiB、最多 64 个结果集。仍排空协议结果以执行后续语句。单个大字段解码、列元数据和驱动自身缓冲属于额外内存。
- 表数据每页最多 1,000 行、保留值数据 8 MiB；只绘制可见行/列，编辑时只复制被修改的行；新行最多暂存 1,000 行，TSV 文件及单次导入暂存最多 8 MiB。多个表页各自持有缓存，这些限制不是整个进程的总内存上限。
- 表格单元格预览最多排版 160 个字符、二进制预览最多 64 字节，避免裁剪区域外的长文本仍生成大量字形；复制和打开编辑器时仍使用完整原值。
- 同连接多个查询/表标签共享一个数据库会话；最后一个相关标签关闭时断开连接，避免每打开一张表就创建新连接。
- Tokio 使用 2 个工作线程，最多 4 个阻塞线程。关闭标签通过 RAII 释放进程、会话和服务。
- wgpu 使用 MemoryUsage 分配提示，交换链最多排队一帧。
- 原生 RDP 的图像通道容量为 1；当前局部更新实现保留一张 canvas 并合并尚未显示的变化范围，UI 取走合并区域，不积压历史屏幕，也不会因覆盖局部帧丢失其他区域。Windows 剪贴板与协议 future 在 GUI 线程由事件唤醒驱动，不额外增加线程；关闭标签直接释放传输和图像资源。
- SVG→PNG 直接保存渲染缓冲，省去 PNG 再解码产生的完整 RGBA 副本；目录转换逐文件处理。

## 重复测量

2026-10-16 工作区新增约束（本轮 release 实测另列于表格）：后台任务在全局准入时限制为 64 项、载荷 32 MiB，并限制同时执行 4 项；串行会话队列也占用上述额度。JSON 历史只驻留摘要，读取和改写逐条流式进行；JSON 输出的长行采用稀疏字形索引，仅向字体系统提交当前水平可见区；输入 TextEdit 仍需排版完整文档，不能把该优化宣称为整个 JSON 编辑器虚拟化。非活动 SSH 标签继续排空协议数据和处理外部编辑，但暂停每秒监控查询。上述约束不能替代最终工作集和私有提交量测量。

```powershell
cargo build --release --locked -p tomato -p tomato-cli
./packaging/measure-memory.ps1 -Executable ./target/release/tomato.exe -Output ./target/memory-release.json
```

脚本默认预热 15 秒，再每秒采样一次，共 10 秒。它使用独立临时目录，仅停止自身创建的测试进程，保留 JSON 记录。设置 WGPU_BACKEND 可单独比较后端；记录中包含这个覆盖值。
在便携包中将 Executable 参数改为 ./tomato.exe，并将 Output 改为希望保存 JSON 的位置。
输入历史和查询结果的上限用于约束保留数据，不能当作整个进程的内存上限。

应用自身的渲染截图可通过 TOMATO_UI_CAPTURE 指定 PNG 路径，完成后自动退出；TOMATO_UI_PREVIEW 可取 json、tools、types、database、rdp、markdown。database 预览需要隔离配置中含 SQLite 连接及名为 orders 的测试表；rdp 预览仅自动打开用户名为 fixture 的本机回环 RDP 测试连接；markdown 使用 TOMATO_UI_PREVIEW_PATH 指定隔离 Markdown 文件。仅显式启用截图时才接受预览参数，普通启动不进入诊断视图。

用户重新连接桌面后，0.1.4 的 SSH 原生窗口截图夹具恢复并通过；离屏图用于全宽布局对照。最终便携包的内存数据另行记录，原先的断开会话失败不计入有效测量。
