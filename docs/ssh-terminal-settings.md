# SSH 终端标签配置

对照原 Java `SshTerminalConnectHandler.createSshTerminalTab`、`LocalTerminalConnectHandler`、`SessionConfigDialog` 和 `ConnectModule` 的 SSH 设置页：

- SSH、本地终端标签右键为“复制会话”、分隔线、“会话配置”、“全局配置”；SSH 文件/管理标签提供后两项。操作目标为右键点击的标签。
- 复制会话读取当前连接配置并创建独立 shell，不复用旧终端缓冲区，不重复执行容器标签的初始命令。
- 会话对话框提供回滚行数、默认文件视图，以及各自的“使用全局配置”。确定后写入原 `scrollbackLines`、`defaultFileViewMode` 字段；继承用 JSON null 表示。SSH 不显示、也不写入 RDP 打开方式。
- 会话配置保存成功后更新该连接的已打开终端；取消不写文件。保留加密凭据、连接 ID、分组、未知字段，沿用备份和外部修改冲突保护。
- 全局菜单直接选择设置中的“SSH终端”页：可输入和选择的字体名称、字号 6–48、回滚行数、服务管理、默认文件视图、字体预览、“应用并保存”。RDP 全局菜单仍直接选择“远程桌面”。
- 应用字体后更新已打开的 SSH/本地终端；更新回滚行数时会话覆盖优先。新终端、SSH 工具标签和容器终端也读取原字段。终端协议和连接无需重启。

回滚预算在 vt100 主屏幕中原位修改：保留解析状态、颜色、光标、屏幕和备用屏幕状态；删除超额的最旧历史并收缩队列，视口和选择不会引用已删除的行。不预分配配置数量的行。

原 Java 设置页把 0 标注为“无限制”，但 `TerminalEmulator.setMaxScrollback(0)` 的实际行为是清空并不保留历史。本版沿用实际行为，未复制该误导标签。持久化仍接受 Java int 范围，去除此前 100000 行的保存限制。

系统字体枚举及字体文件读取在短期后台任务中执行。字体预览与已应用字体分别使用一个可替换槽；快速输入字体名合并到一个加载任务，不按输入次数保留字体或加载线程。等宽默认字体共享已加载字节，未知字体名称回退。

验证入口：工作区默认测试中的 `app::session_config::tests`，以及 `scripts/qa/ssh-tab-menu.ps1`（真实本机 SSH、原生菜单/会话/全局页截图，合成 egui 输入，独立配置；不连接保存的用户主机）。这不代表全部终端行为或全部界面像素已完全一致。

本轮补充：本地 PTY 释放顺序调整为先关闭输入和断开输出接收，再释放伪控制台；接收端消失后读取线程无分配排空尾部输出。单独的 Windows 初始关闭与输出积压关闭用例通过。配置交互测试使用隔离无进程传输；原生 SSH 菜单验收另测复制后的两个独立连接，避免把本地控制台启动当作配置界面测试的一部分。

全局页面使用轻量编辑草稿，只保存当前子页的字段。未点“应用并保存”的值不会影响运行终端或新连接；全局文件被外部修改而保存失败时，已生效设置与编辑草稿分别保留。系统/RDP 页的保存不会顺带提交 SSH 草稿。默认工作区回归已通过 512 项，73 项外部夹具用例保持忽略；真实本机 SSH 开发窗口四场景通过。1114 正式 EXE 的四个真实 SSH 场景、正常退出、图标和同批空闲内存对照均已通过，记录见 `target/ssh-menu-acceptance-1117.json`。
