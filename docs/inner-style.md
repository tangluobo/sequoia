# 设计器工具栏、网格与内部标签

本轮对应用户报告的设计表按钮样式、重复网格边线，以及查询结果、RocketMQ 消息内部标签未沿用原版样式的问题。主窗口标签、原有连接格式和协议实现不在本轮改动中。

对照原 Java 当前 `TableStructureView.java`、`SqlEditor.java`、RocketMQ 页面以及 `connect-tree.css` / `tab-nogap.css`。原 Java 表设计器重新编译到本项目的隔离测试目录，加载原资源和父级全局样式；只使用内存里的合成 JDBC 元数据，不连接保存的服务器，也不修改原 Java 工程。单独运行而未加载父级 CSS 的旧截图不能作为工具栏样式的依据。

## 实现

- 设计器主工具栏恢复 35px 高度、26px 按钮、原图标和位置；按钮使用方角、浅灰底色及原悬停/按下边框。索引、外键、触发器等页复用相同按钮绘制，保留原有动作。
- 网格单元格各自只绘制右边和底边，选择列负责左边，避免相邻单元格同时描边形成双线。保持原表头、行高、列宽、颜色和编辑命中位置；一帧完成绘制后再更新拖动后的列宽，避免表头和数据行暂时错位。
- 设计器七页、查询结果以及脚本信息/结果/执行计划/状态使用 25px 的内部标签；Kafka、RocketMQ 主页面及消息查询条件使用 33px 标签。高度差来自原版的两套 CSS，不能全部套用 37px 主窗口标签。
- 统一内部标签的方角、底色、12px 字体度量、单侧边线、选中黑色底线。接通横向溢出菜单、当前项标记、选中项滚入视野，以及有焦点时的方向键/Home/End 切换。手动滚动不会每帧被拉回当前项。

复用现有字体与图标，不增加字体文件副本、常驻纹理、持续刷新或业务数据缓存。标签仅临时保存少量标签文字布局引用；网格仍按可见行绘制。没有修改 Cargo 依赖、连接序列化、数据库命令或 MQ 请求实现。

## 验证范围

`scripts/qa/inner-style.ps1` 对自己的独立配置和自建进程截图，覆盖设计器七页、多行网格、Kafka/RocketMQ 宽窄窗口、脚本信息/结果和数据库信息页，共 15 种窗口状态。`scripts/qa/compare-inner-style.py` 校验实际截图的尺寸、原版标签几何与边线颜色、工具栏高度，以及多行网格的单像素分隔线。对应原 Java 证据位于 `target/inner-style-oracle-359`，其中 `identity.json` 记录原源码与资源哈希。

内部标签回归测试使用实际 UI 指针、焦点、键盘和溢出菜单交互；主窗口原有四种标签状态另行回归，标题栏底线必须继续可见。测试不会自动连接用户保存的数据库或 MQ。

这些检查不代表全应用逐像素一致：原 Java 表头中文使用 System Bold，而当前 Rust 表头中文仍使用已有常规字体；字形光栅和部分度量也存在差异。截图证明明确记录 `allGlyphPixelsIdentical: false`，没有把结构边线一致写成所有文字像素一致。

格式、严格 Clippy、全目标开发构建、409 项默认工作区测试和 CLI 自检通过，62 项条件测试默认忽略。开发版 15 种状态的结构与边线比较通过，汇总证据为 `target/window-probes/inner-dev-validated-359/style-proof.json`：其中 Kafka 窄窗口第一次截图仍为调整前的 1200px 表面，日志记录当时正在切到 900px，该图片保留但排除；将等待时间从 2 秒增加到 5 秒后，仅重测这一状态并通过，汇总记录两个原始证据目录，没有覆盖失败图片。
