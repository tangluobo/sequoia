# Java 功能迁移与真实环境验证（1690）

本轮沿用原 Java 的功能入口和加密配置格式，集中修复 Oracle 原生会话与结构读取，并完成 Docker、Linux 存储管理的真实后端验证。全应用迁移及视觉对等仍未全部完成。

## Oracle 实际路径修复

- 保留原生错误的类型和原因链。断线、关闭、超时及损坏的 TTC 会话进入共用有界恢复流程；SQL 和类型错误不自动重放。
- 连接失效时中断并释放所属套接字。只读表页及结构查询最多重连三次，丢弃旧 SSH 通道后重建；用户写操作和丢失的事务不自动重新执行。
- 初始化仍有超时保护，普通用户 SQL 不再受到统一 30 秒调用超时限制。取消操作仍可中断套接字。
- 将 Oracle 匿名 PL/SQL 单元与显式事务区分，避免执行脚本后错误阻止只读恢复。
- 原巨型系统目录联接改为按 owner/table 分别读取字段、注释、主键和标识列，打开表与表设计器共享读取器。完整 LONG 默认表达式保留，字段数及保留内存有界，原设计器签名顺序保持兼容。
- 采用 Oracle 官方上游提交 `e258557c38f52467f3f59d727c22390ed80144ec` 中 LTXID、AC_REPLAY 双层长度读取修正，新增跨包边界检查；保留原有响应预算。

隔离 Oracle Free 23.26.3 已实际完成直连表页读取、数据修改回读、35 秒 PL/SQL 和杀死所属数据库会话后的自动恢复。Oracle 经 SSH 连接的首轮实际尝试在连接阶段超时；后两次隔离环境健康检查失败，未开始恢复验收，因此 SSH 实际恢复未通过。所有所属虚拟机已停止。

## Linux 与 Docker

Docker 使用原生 SSH 连接真实隔离 Linux Docker 服务，验证内存/交换空间、CPU/权重、重启策略、无效资源拒绝、停止/启动及读回。

存储管理使用两份独占临时磁盘映像，核对循环设备实际后备路径后执行正式 Rust 命令：初始化 PV、创建及扩展 VG、格式化和挂载、带空格路径的 fstab 重挂载、在线扩容、无效 LV 拒绝以及数据保持。正式 Rust 清单解析器核对实际 lsblk/LVM 输出。验收使用 Windows OpenSSH 执行真实命令；原生 SSH actor 路径由另行记录的加密协议回归覆盖。临时 VG、PV、循环设备及客体 fstab 均已清理恢复。

## 已知验收边界

Oracle 完整复制测试在软件仿真的隔离环境中，达到 2400 秒验收时限时仍执行服务器 `DBMS_METADATA` 内部 `SYS_XMLGEN(KU$_FHTABLE_VIEW)` 查询；尚未完成完整复制及后续 NB3 备份还原。此前还独立保留了原版巨型目录查询超时、原 30 秒调用超时、官方 SQL*Plus 连接失败及虚拟机时钟跳变的记录，不能将这些尝试计入通过数。

本轮没有连接用户保存的主机，没有修改原 Java 项目、系统虚拟化功能或原加密配置。原生界面捕获、空闲内存配对、完整工作区检查与交付哈希记录随正式发布包提供；不据此声明所有真实硬件、远程网络与全应用像素对等已经验收。
