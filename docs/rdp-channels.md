# RDP 图形、文件剪贴板与声音

2026-10-21 验证成品：`target/qa-candidate-rdp-shared-613/tomato.exe`，同目录 build-info.json 记录哈希与证据。本次为 GUI 候选，不附带旧 CLI。全屏变化仍有卡顿，未达到用户要求的流畅度，不能计作迁移完成。

独立 RDP 窗口使用由应用处理的延迟视口，网络画面只唤醒对应窗口；连接状态改变才同步刷新主界面。网络和解码在独立 tomato-rdp 线程，Windows 剪贴板窗口仍由 GUI 线程管理。子窗口关闭按实际视口 ID 判断，最小化期间的输入按窗口隔离；嵌入式后端保留回退。原生窗口关闭/最小化生命周期，以及优化成品的标签、独立窗口、全屏验证通过。

本轮对照只读 Java rdp4j 的 DrdynvcChannel、ClearCodecDecoder、FixedClipChannel 和 WindowsVirtualFileClipboard，接入实际 Rust 会话。旧连接的 mapClipboard、enableSound 字段直接生效，没有修改配置格式。

## 图形

实际协商 SUPPORT_DYN_VC_GFX_PROTOCOL，在 DRDYNVC 注册 Microsoft::Windows::RDS::Graphics。使用原 Java 对应的 V10 AVC_DISABLED / V8 回退，处理 ClearCodec、Progressive、表面映射、缓存与复制、EndFrame 和帧确认；尚未接入 AVC 视频解码。普通位图和 RemoteFX 路径保留。

脏区进入已有有界帧合并和局部纹理上传链路，不逐条带重绘窗口。同为 RGBA 的图形更新逐行复制，保留光标合成与输入长度检查，避免逐像素的通道重排。没有 EndFrame 的首个有效 Progressive 登录画面提前显示，确认仍等待真实 EndFrame。普通 RDP 按需创建 ZGFX 历史。表面/缓存共享 256 MiB 上限；Progressive 最多 128 个上下文，保留状态估算共享 384 MiB 上限，单次最多 4096 个 64×64 瓦片。这些是上限，不是预分配。

ClearCodec 的残差连续像素先限制写入范围、再整像素写入；BGRA→RGBA 复用解码缓冲。后续帧回收解码暂存区，按需保留不超过 64 MiB，未写入像素仍清零，缓存与异常包语义不变。服务层整帧以 Arc 共享快照交给注册的原生 WGPU 纹理，局部更新仅复制、上传脏区；软件回退保留。RDP 只消费快照，VNC 才消费旧帧接口，防止两条消费路径争抢脏区造成黑屏。

mimalloc 试验已撤回，当前 GUI 使用 Windows 系统分配器，运行时未新增该依赖。保留旧试验记录供对照，不能把不同窗口模式的内存差异归因于分配器。应用层继续禁止 unsafe，画质、分辨率和旧配置不变。

10 个有状态 ClearCodec 样本由原 Java 解码器独立执行，并比较 Rust 输出，包括未写入 VBar 缓存的黑色、短条带及缓存重置。复现脚本 scripts/qa/rdpgfx-java.ps1 不写 Java 项目、不连接保存主机。

## Windows 文件复制

适配器实际包裹会话的 CLIPRDR 后端。本地文件通过 CF_HDROP 枚举；远程文件通过 FileGroupDescriptorW、SIZE/RANGE 与锁定 ID 按需读取。Windows OLE IDataObject/IStream 由 MIT 库 virtual-file-transfer 提供，保留目录、相对路径、大小和修改时间；不预先下载整文件。

另一 RDP 会话复用原远端流源，实现远程 A 复制、远程 B 粘贴，无整文件中间副本。两端必须允许剪贴板文件重定向，源会话需要保持连接。当前是复制语义；剪切后删除、拖拽及磁盘映射尚未实现。

延迟启动的全局文件队列最多 8 项，每次最多 1 MiB，每会话最多 4 个未完成读取、16 个本地锁定列表、64 个远端快照 ID、10000 个文件描述符，目录深度最多 64。重连时重建通道状态，锁 ID 同时关联文件清单代次，旧流不能借用新会话重复的 ID。断线、撤销锁定、失效代次和超时结束等待；迟到响应再次检查代次与锁，过期流不会改读新的文件列表。路径验证、符号链接拒绝和源文件变化检查防止返回错误数据。队列满时返回失败，不阻塞 GUI。Ctrl+C/V 原始按键与语义事件去重，避免双重操作。

发布由原生隐藏剪贴板 HWND 的消息处理，不依赖 egui 重绘；关闭会话销毁 HWND 并释放回调和文件源。回环协议测试覆盖中文文件、空目录、超过 2 MiB 的文件、跨会话流式转发、分块限制与断线取消。测试不操作用户系统剪贴板；不能据此声称所有 Explorer/第三方文件管理器兼容性已验收。

## 声音

实际会话启用 RDPSND 和 CPAL 后端，遵循旧 enableSound 开关。音频线程显式启动输出流；PCM 与 Windows 默认设备的浮点格式、采样率及声道不一致时，实时回调做有界转换。回调读取无锁环缓冲，不等待网络；欠载填静音。

PCM 缓冲按解码后的约 125 ms 计算，最多 256 KiB；Opus 队列最多 8 个包、每包 64 KiB，解码上限 120 ms。设备打开失败间隔 2 秒重试，避免每个音频包创建线程；关闭释放输出流。本轮仅远程播放，未启用麦克风重定向。

## 来源与验收边界

IronRDP 固定在 0f9154d2128f8c65f4d51f6b7eb7cb1d66a12329，各 vendor 保留许可证和 TOMATO_UPSTREAM.json。应用仍禁止 unsafe；Win32 窗口调用由原生依赖封装。

协议通过不等于实际保存主机已流畅。原生窗口、优化成品性能、声音设备结果单独记录在 target 验收证据。合成源 UI 提交率不是实际网络端到端延迟或物理显示帧率；不能据容量上限宣称进程内存下降。

用户明确授权后，使用旧加密配置中的“110”完成真实协议连接与 1920×1080 收图。当前源码的最后一次检查为首批像素 2107 ms、连续观察 25.43 秒、10 次图像更新，原配置字节未变，证据 `target/rdp-saved-110-shared-612.log`。该次有编译任务，不能与先前 1005/1170 ms 比较性能。未发送远程键鼠、未改远端文件；协议测试在内存关闭剪贴板，不能证明 Explorer 文件粘贴、交互延迟或声音听感。测试默认忽略，要求显式授权标记及新输出路径。

当前默认回归 469 项通过、70 项条件测试忽略；格式、严格 Clippy、全目标开发构建和 CLI 自检通过，见 `target/rdp-shared-validation-615.json` 与 `target/rdp-shared-*-611.log`。图形库 254 项、EGFX 63 项、原 Java 有状态样本 10 项通过。先前文件协议 5 项、音频协议 4 项、默认输出设备静音消费 1 项、隐藏 HWND 生命周期 1 项及会话 46 项通过；这些不替代实际 Explorer 操作与远端声音听感验收。

优化成品三种静态窗口、标签/独立窗口局部与整屏动态检查通过；静态远端画布与基线逐像素一致，局部更新保留背景。合成源测量为：1080p 整屏标签约 30.67 次更新/秒、独立窗口约 26.22 次/秒，独立窗口最大间隔约 140 ms；小范围变化独立窗口约 56.03 次/秒。证据 `target/rdp-shared-acceptance-613.json`、`target/window-probes/rdp-shared-sparse-613`。这不是远程 110 的帧率、端到端延迟或物理显示帧率。与初始 533 的约 10.31/6.39 次/秒相比有改善，但不能认定已经流畅。
