# 1692：继续逐项迁移

本轮直接修改现有应用的会话工厂、原生对话框和 Oracle 传输驱动，旧加密配置无需转换。没有改写 Java 参考仓库，也没有使用保存的远程连接进行网络测试。

## Redis 集群经 SSH

原生集群工厂读取既有 `redisClusterNodes`、`useSshTunnel` 和跳板引用/内联字段。种子、拓扑发现、MOVED/ASK 重定向及逐主节点 SCAN 均通过同一作用域解析器建立 SSH 转发；保留原 Redis 地址供 TLS SNI 和证书验证使用。原 UI 与命令入口共用该工厂，无需新增按钮或重复配置。

节点转发按地址复用，以 128 个为上限；同一集群会话仅认证一条 SSH 连接，由各节点共用，不持锁等待网络。失败槽位可重建，取消/关闭会话清除节点表并中止所属通道，引用跳板时不保留整个连接配置仓库。没有新增全局会话或无限缓存。

原 Java `RedisService.createJedisCluster` 本身直接构造集群地址，并未取得单机 Redis 使用的 SSH 租约。因此集群 SSH 是原生补全能力，不称为 Java 已有能力的对等验收。原先直接集群、单机 SSH/TLS 的路径保留。

独立加密 SSH、RESP 与 TLS 组合测试已通过，包括两类重定向、ASKING 顺序、认证、主机名验证、各主节点扫描、字面 IP、节点数量上限和所属连接关闭。三个真实 Redis 7.4 主节点的实际读写、值回读、类型、TTL、跨槽删除、原始命令及全主节点扫描已通过，耗时 88.12 秒；独立加密配置字节和未知字段未改变。镜像摘要 `redis@sha256:c5d34a98396a4775e223c74e929162c35c5a2182901ba26b50ade939941ce14b`，证据见 `target/migration-1692-redis-real-final-c.json`。测试仅使用本轮 Linux 虚拟机内的合成账号和独立加密配置。

## 原生弹窗位置

对照 Java `utils/DialogPositionUtil.java`，消息框、连接导入和导出窗口改在所属显示器的可用工作区域中居中，避免按主窗口中心定位到屏幕接缝或任务栏。嵌套提示以向导窗口为 owner。Windows 适配器只读取 GetMonitorInfoW；不修改显示设置。

工作区域保留物理像素，创建后按子窗口实际 DPI 和含系统边框的尺寸校正，DPI/尺寸稳定后停止定位，不持续抢回用户拖动的位置。超大窗口以工作区域左上角对齐；缺少原生几何时保留原回退。非 Windows 工作区域查询和真实混合 DPI 多屏手动验收仍独立保留。

## Oracle 分包恢复

修复传输层只收到完整包头但包体尚未到齐时提前移动消费游标的问题。读取超时后继续接收时，原半包不再被移除。独立 TCP 测试先发包头、触发一次读取超时，再发剩余包体及下一包，核对两个消息的原字节与边界。旧实现的失败日志和修复后十项驱动测试通过记录均保留。

这不等于 Oracle SSH、完整复制或备份还原已通过。实际 Oracle 虚拟机再次遇到软件仿真下的时钟漂移和数据库启动期限；镜像无 Docker Health 字段，不能把读取该字段失败解释为数据库健康检查失败。所属虚拟机已关闭，共享配置摘要未变更。原有直连成功及复制元数据超时记录保留。
